## النطاق المنفذ مقابل متطلبات الخطة

| المتطلب الرسمي | التنفيذ |
|---|---|
| سجل مالي append-only بنمط أحداث الطلبات | `ledger_entries` بقيد إتمام لكل طلب completed (مبيعات + توصيل + عمولة بنسبة الخطة **snapshot**) وقيد عكسي عند الإرجاع — trigger قاعدة بيانات يرفض UPDATE/DELETE نهائياً |
| حسم نافذة الإرجاع | 15 يوماً: عكس تلقائي داخلها في نفس المعاملة؛ خارجها مسار تسوية يدوية للمالك فقط (append-only بمنع تكرار) |
| تقارير مفهرسة | تقرير التاجر (مستحقاته بالفترة عبر متاجره + آخر القيود) وتقرير المالك (لكل التجار + الإجماليات) بجمع موقّع، على فهارس مخصصة |
| دورة تسوية | المالك تسجّل تسوية فترة بلقطة إجماليات محسوبة لحظتها — سجل `settlements` append-only محمي بنفس القوة، ويظهر للتاجر |
| النطاقات | حل خادمي `custom_domain` ثم `default_subdomain`؛ الواجهة تهبط بجذر نطاق المتجر إلى واجهته مباشرة (`?codiq_host=` لتغطية الاختبار) |
| الموقع التعريفي + التسجيل الذاتي | صفحة هبوط تسويقية حقيقية (مزايا + أسعار حية من `/api/public/plans` بعمولة معلنة + نموذج تسجيل يعمل) بسياسة auto/manual بمفتاح منصة تديره المالك، وحد slug من المرحلة 13 وخطة Free من 16 |

## عقود API الجديدة

| المسار | التفويض | الوظيفة |
|---|---|---|
| `GET /api/merchant/finance/report?from&to` + `/settlements` | جلسة تاجر | مستحقات الفترة + التسويات المسجلة |
| `GET /api/platform/finance/report` | مالك المنصة | إجماليات وتفصيل لكل تاجر |
| `POST /api/platform/finance/settlements` | مالك المنصة | تسجيل تسوية بلقطة — `201` |
| `GET /api/platform/finance/settlements/:merchantId` | مالك المنصة | سجل تسويات تاجر |
| `POST /api/platform/finance/adjustments` | مالك المنصة | قيد إرجاع متأخر يدوي — `409 ALREADY_REVERSED` عند التكرار |
| `GET/PUT /api/platform/settings/registration` | مالك المنصة | سياسة التسجيل auto/manual |
| `GET /api/platform/merchants/registration-requests` + `POST .../:id/approval` | مالك المنصة | طابور الطلبات والموافقة/الرفض |
| `GET /api/public/plans` · `GET /api/public/store-for-host` · `POST /api/public/merchants/register` | عام (بحد معدل للتسجيل) | أسعار الصفحة العامة، حل النطاق، والتسجيل الذاتي |

## ملاحظات معمارية

- الفرض المالي داخل معاملة الانتقال نفسها يعني استحالة طلب مكتمل بلا قيد أو قيد لعملية متراجعة — نفس فلسفة outbox المرحلة 15.
- طلب يُرجع من التوصيل دون أن يكتمل قط (`out_for_delivery → returned`) لا يمس السجل (لا قيد إتمام أصلاً) — واقعية COD.
- جمال مسارات النطاق المخصص بلا بادئة `/store/…` مؤجل عمداً لطبقة theming (المرحلة 21) — الوصول عبر النطاق يعمل الآن.
