## 20B-3 — التفاصيل والأدلة

### استيراد/تصدير CSV (D-25)

- **Parser يدوي** RFC-4180 جزئي (~60 سطراً، `phase1-backend/src/services/csv.ts`، صفر تبعيات): حقول مقتبسة بفواصل وأسطر جديدة واقتباسات مهرَّبة `""`، CRLF/LF، إسقاط BOM، وحالات وحدة داخل `phase20b3.integration.mjs` (11 حالة تشمل round-trip للمُسلسِل).
- **الاستيراد** `POST /merchant/stores/:slug/catalog/import/products` (multer ذاكرة بسقف 2 MB، حارسا `catalog.products.create` + `requireTrustedWriteOrigin`): صف لكل متغير بتجميع `product_sku` — أول صف لكل منتج ينشئه **بمسار createProduct نفسه** (الـtrigger ينشئ المتغير الافتراضي داخل المعاملة ثم حقول الصف الأول تحدّثه)، والصفوف التالية متغيرات إضافية. `category_path` («أب > فرع > ورقة») يُحسم على الشجرة المتشعبة بحد العمق 3 وينشئ العقد الناقصة عند التنفيذ، مع رفض التعارض (`normalized_name` فريد بالمتجر).
- **معاينة إلزامية**: `?dryRun=true` يعيد `{totalRows, newProducts, newVariants, errors:[{row, column, code, message}]}` **بصفر كتابة** (مثبت بعدّ المنتجات والمتغيرات والتصنيفات والحركات قبل/بعد).
- **التنفيذ**: معاملة واحدة **كل-أو-لا-شيء** بسقف 2000 صف (`CSV_TOO_LARGE`)، إنشاء فقط (SKU موجود — منتجاً أو متغيراً — = خطأ صف `SKU_EXISTS`)، UTF-8 حصراً (`CSV_INVALID_ENCODING` برسالة عربية واضحة)، و`assertWithinPlanLimit(tx, merchantId, "max_products", newProductsCount)` **مرة واحدة قبل أي إدراج** — تجاوز الحد = 403 `PLAN_LIMIT_EXCEEDED` بلا إدراج جزئي (مثبت).
- **التصدير**: `GET …/catalog/export/products.csv` (`catalog.products.view`) و`GET …/orders/export.csv?from&to&status` (`orders.view`) — بث `response.write` بترقيم cursor (صفحات 200)، **BOM UTF-8 أولاً** لسلامة العربية في Excel، و`Content-Disposition`. تصدير المنتجات بنفس أعمدة الاستيراد (round-trip مثبت: تصدير متجر → استيراده في متجر جديد بأسعار وخيارات وشجرة تصنيفات مطابقة). تصدير الطلبات صف لكل بند (variant-aware: SKU واسم المتغير) مع أعمدة الطلب (الرقم/الحالة/الزبون/المجاميع/الخصم/`coupon_code`).
- **ملاحظة تسجيل**: مسار التصدير سُجل **قبل** مسار `orders/:orderId` حصراً (Express يطابق بالترتيب و`export.csv` كانت ستُلتقط كمعرّف طلب)؛ المسار الحرفي كان يعيد 404 سابقاً فلا تغيير بأي سلوك قائم.
- **UI**: تبويب «استيراد/تصدير CSV» في `ProductCatalogManager` (رفع → جدول معاينة الأخطاء → تأكيد لا يُفتح إلا بمعاينة نظيفة) وزر «تصدير CSV» بمرشحات القائمة الحالية في `OrderWorkspace` (نطاق التاجر فقط — لوحة المالك بلا تصدير).

### البكسلات الإعلانية (D-26)

- **الهجرة** `20260827090000_phase20b3_marketing_pixels` (إضافية بالكامل): `store_marketing_settings` بنمط `notification_settings` — `store_id UNIQUE FK CASCADE`، ثلاثة معرّفات، `is_enabled` افتراضه **معطل**.
- **تحقق صيغة صارم في الخادم** (خط دفاع الحقن): Meta `^[0-9]{5,20}$`، TikTok `^[A-Z0-9]{10,30}$`، GA4 `^G-[A-Z0-9]{4,20}$` — أي شيء آخر (سلاسل XSS، معرّفات UA، حروف صغيرة…) = 422 `INVALID_PIXEL_FORMAT` **ولا شيء يُخزن** (8 أشكال خبيثة مثبتة). الإعداد بحارس `settings.manage` في `GET/PUT /merchant/stores/:slug/marketing/integrations`، والواجهة `MarketingIntegrationsPanel` على `/merchant/dashboard/settings/integrations`.
- **`GET /store/:slug/public-config`** عبر `resolveStorefrontStore` (متجر نشط فقط — المعطل 404): مفتاح `pixels` **غائب** عند التعطيل أو الفراغ، وحاضر فقط بمعرّفات أعيد التحقق من صيغتها عند القراءة (دفاع متعمق). عزل متجرين مثبت.
- **الحقن حصراً في `StorefrontProvider`** — ضمان بنيوي: اللوحات لا تركّب هذا المزوّد أبداً، فلا يمكن لأي صفحة لوحة تحميل سكربت تسويقي (مثبت في المتصفح: `window.fbq` غير معرّف ولا وسم سكربت خارجي في أي صفحة لوحة). المقتطفات الرسمية (fbq/ttq/gtag) تُحقن مرة واحدة بمعرّفات محقَّقة، والأحداث client-side: `PageView` عند كل تغيير مسار، `AddToCart` بعد نجاح `addCartItem` (قيمة سعر المتغير المختار)، و`Purchase` عند نجاح checkout **فقط حين `!result.replayed`** (قيمة `totalIqd` بعملة IQD) — إعادة المحاولة idempotent لا تُعدّ مرتين (مثبت في المتصفح: حدث purchase واحد بالقيمة الدقيقة).
- **Conversions API مؤجل صراحة** إلى 24/25 (موثق في الواجهة والخدمة).

### ملاحظة CSP المستقبلية (D-34)

لا CSP اليوم. عند اعتماد helmet تُسمح النطاقات الثلاثة **لصفحات المتجر فقط** في `script-src`/`connect-src`:
`connect.facebook.net` · `analytics.tiktok.com` · `www.googletagmanager.com`
وصفحات اللوحات تبقى **بلا أي أصل سكربت خارجي** — الملاحظة نفسها موثقة في `marketing-settings.service.ts` و`storefront-pixels.ts`.

## البوابات

- **`phase20b3:test` حاجبة في CI** (بعد `phase20b2:test`): حالات وحدة الـparser؛ dry-run بصفر كتابة؛ التنفيذ يبني منتجاً بثلاثة متغيرات بأسعار ومخزون دقيقة وسلسلة تصنيفات بعمق 3 وإعادة تسمية المتغير الافتراضي وحركات `initial_stock`؛ صف واحد سيئ يرفض الملف كله (422 وصفر إدراج)؛ تجاوز حد الخطة = `PLAN_LIMIT_EXCEEDED` بلا إدراج جزئي؛ إنشاء-فقط وسقف 2000 والترميز المكسور والحدود بين المتاجر؛ عزل التصنيفات بين متجرين؛ round-trip تصدير→استيراد بمتجر ثالث؛ شكل صفوف تصدير الطلبات (صف لكل بند + كوبون + مرشح الحالة + 403)؛ صيغ البكسلات الخبيثة 422 وبوابة public-config (معطل/موقوف/متجر غير نشط) وعزل متجرين. درسا الحزمة مطبقان: تنظيف `storefront_rate_limits` قبل كل كتابة، ولا مساس بـ`notification_outbox`.
- **`phase20b.browser-acceptance.mjs` موحّد** في job المتصفح (غير حاجب، منفذ 3202، بعد خطوة 20A): كوبون يُدخل في checkout فيظهر صف الخصم ويكتمل الطلب؛ رحلة منتج الوصفة كاملة (رفع → «قيد المعالجة» معطلة بسبب مسبب → اعتماد التاجر → الانتقال ينفتح)؛ صفحة التحليلات تعرض الإيراد المحقق الدقيق (١١٬٥٠٠ د.ع) بعد إكمال الطلب؛ إنشاء كوبون من `CouponsManager`؛ تفعيل لوحة السلات المتروكة وبقاؤه بعد إعادة التحميل؛ CSV معاينة ثم تنفيذ والمنتج يظهر في القائمة؛ البكسلات محقونة في صفحة المتجر (fbq/ttq/dataLayer + وسوم السكربت الثلاثة) **وغائبة كلياً عن HTML اللوحات**، مع حدثي add_to_cart وpurchase بالقيم الدقيقة.
- محلياً: `phase1:db:generate` ✓ `check` ✓ `phase1:typecheck` ✓ `build` ✓ `node --check` للاختبارين ✓ وحالات وحدة الـparser خضراء عبر tsx.

## تحديث حالات القوائم عند إغلاق 20B

- تاجر: «التكاملات» (الإعدادات) → **implemented** (D-26)، وأضيف «استيراد/تصدير CSV» تحت المنتجات → **implemented** (D-25). («الكوبونات»، «تقارير الطلبات/التسويق»، «السلات المتروكة» صارت implemented في دفعتيها.)
- شارات «20B»/«20» المتبقية لم تعد صادقة بعد الإغلاق فأعيد تسكينها: «العروض» و«الحملات» → «25ب» (قرار §8.15: العروض تُدار عبر الكوبونات حتى موعدها)، «الموقع التعريفي» (لوحة المالك) → «21+»، «تقارير الطلبات» (لوحة المالك) → «24» — 20B سلّمت تحليلات **التاجر**؛ تقارير المنصة تُبنى مع دفعة التشغيل — و«المطورون» (لوحة المالك) → «24» مع دفعة التكاملات. هذه التسكينات قابلة للتعديل بقرار المالك.
