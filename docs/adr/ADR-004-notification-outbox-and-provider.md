# ADR-004 — إشعارات Outbox المعاملاتية، قناة أولى، وعامل معالجة مستقل

**الحالة:** معتمد بموجب التفويض الكامل الممنوح من المالك (2026-08-25) لإكمال المشروع واتخاذ قرارات الخطة المفوضة، مع شرط الجودة التنافسية.
**التاريخ:** 2026-08-25 — المرحلة 15.

## السياق

تشترط الخطة الرسمية إشعار التاجر والزبون بالأحداث (order.created،
order.status_changed، low_stock) دون الاعتماد على طابور مملوك لمزود خارجي،
عبر جدول notification_outbox يُكتب في نفس معاملة العملية الأصلية، وعامل
معالجة منفصل، وطبقة Provider abstraction بمزود حقيقي واحد أول.

## القرار 1 — القناة الأولى: البريد الإلكتروني عبر SMTP مجرد

- تُنفذ قناة البريد بمزود SMTP عام (nodemailer) يُهيأ حصرياً بمتغيرات بيئة
  خادمية (`CODIQ_SMTP_HOST/PORT/USER/PASS/FROM/SECURE`). لا secrets في
  قاعدة البيانات أو الواجهة أو السجل.
- **لماذا البريد أولاً:** SMTP لا يتطلب عقداً مسبقاً ويعمل مع أي مزود تختاره
  المالك لاحقاً (Resend/SES/Postmark/بريد مؤسسي) بتغيير env فقط؛ بينما SMS
  العراقي يحتاج حساباً تجارياً واعتماداً لم يُوفر بعد. تبقى `sendSms` stub
  صريحاً يعيد `sms_not_configured`، وتُفعل مع مرحلة التكاملات (25).
- عند غياب تهيئة SMTP لا يدّعي النظام الإرسال: تُعلَّم الصفوف `skipped`
  بنتيجة `no_provider_configured` مرئية في سجل التاجر.

## القرار 2 — نمط العامل: عملية نظام مستقلة بجانب الخادم

- العامل ملف تنفيذ مستقل (`dist/worker.js`) يبنيه esbuild من
  `worker-entry.ts`، ويشغَّل كعملية OS منفصلة: يفرخه خادم الإنتاج تلقائياً
  (قابل للتعطيل بـ`CODIQ_NOTIFICATIONS_WORKER=off`) ويمكن تشغيله وحده عبر
  `pnpm phase15:worker` أو كخدمة Railway مستقلة لاحقاً.
- لا timers داخل مسار HTTP إطلاقاً؛ حلقة العامل داخل عمليته الخاصة فقط،
  وbatch المعالجة (`processOutboxBatch`) دالة deterministic تستدعيها
  الاختبارات مباشرة بحقن الزمن والمزود.
- **التسليم exactly-once عملياً:** claim ذري موسوم بـtoken (إعادة فحص الحالة
  داخل التحديث) يمنع عاملين من إرسال الصف نفسه؛ backoff أسّي (30s × 2^n)
  حتى 5 محاولات ثم `dead_letter` بنتيجة آمنة.

## القرار 3 — دلالات الأحداث

- الكتابة داخل نفس `Prisma.TransactionClient` للعملية التجارية (checkout
  Serializable، انتقال حالة الطلب، وكل مسارات إنقاص المخزون).
- low_stock يُطلق عند **عبور** الحد هبوطاً فقط (كان فوق الحد وأصبح عنده أو
  دونه)، فلا يتكرر الإزعاج ما دام المخزون منخفضاً، ويعاد الإطلاق بعد إعادة
  التعبئة ثم عبور جديد؛ مفتاح dedupe فريد يحمي العبور نفسه من أي سباق.
- أحداث التاجر تُبوَّب بتفضيلاته (`notification_settings.configuration.preferences`)
  خلف مفتاح `isEnabled` الرئيسي؛ أحداث الزبون تتطلب المفتاح الرئيسي وعنواناً
  معروفاً. الوصول لإعدادات وسجل الإشعارات محكوم بـ`settings.manage`.

## البدائل المرفوضة

- طابور مزود خارجي (SQS/Cloud Tasks): يخالف نص الخطة ويقيد قابلية النقل.
- الإرسال المتزامن داخل الطلب: يربط نجاح البيع بتوفر مزود البريد.
- SMS أولاً: يتطلب عقد مزود عراقي غير متوفر الآن؛ البنية جاهزة له دون تغيير مخطط.
