## التنفيذ — Pass A (الدفعة القادمة مباشرة بعد 20A-1)

**المحتوى:** شارات «قريباً — المرحلة X» لكل قائمة غير جاهزة (B-13) + 19 قائمة فلاتر طلبات (مالك+تاجر) + دليل التجار مع تفعيل/إيقاف + دمج «إدارة التجار» + قائمة متاجر المنصة (backend S) + صفحات متاجر التاجر وإدارة المتجر (rename S + رابط عام/QR) + قائمة العملاء بفلاترها (backend S — تخدم التاجر والموظف معاً) + صفحة «الدفع» الشفافة + تجميع إعدادات المنصة.
**إضافات خادمية صغيرة ثلاث فقط:** `GET /platform/stores`، `GET /merchant/stores/:slug/customers`، `PATCH /merchant/stores/:slug` (إعادة تسمية) — كلها بنمط الحراس والعزل القائم واختباراتها.
**التقدير:** 4–6 أيام ببوابة انحدار كاملة.

**قرارات صغيرة مطلوبة من المالك (غير حاجبة لبدء Pass A):**
1. تعريف «العملاء المحتملون» = سجّلوا بلا طلبات؟
2. اعتماد دمج ازدواجية العروض/الكوبونات في «التسويق».
3. «التحقق» (KYC): دمج مؤقت مع طلبات التسجيل الآن؟

## القرار النهائي المعتمد — «قوائم أقل، صفحات أذكى» (اعتُمد 2026-08-26)

نُفّذ في Pass A (فرع `menus-pass-a`) وفق موافقة المالك:

### إعادة هيكلة القوائم
- **طلبات المالك:** 11 قائمة ← 5: جميع الطلبات، بحاجة لإجراء، الإرجاع، التسليم، التقارير. فلترة الحالات انتقلت إلى **شرائح (chips) داخل صفحة الطلبات** — والروابط العميقة القديمة (processing/fulfillment/…) تبقى تعمل بفلترها المسبق.
- **طلبات التاجر:** 13 قائمة ← 6: جميع الطلبات، بحاجة لإجراء، الإرجاع، التسليم، التسويات، التقارير — بنفس آلية الشرائح.
- **«بحاجة لإجراء»** = الطلبات الجديدة + قيد المعالجة (دمج عرضين من الـAPI في القائمة).
- **حُذفت** قائمتا المالك «إدارة التجار» (دُمجت في «التجار») و«التحقق» (دُمجت في «طلبات التسجيل»)، وقائمة التاجر «المنتجات ← العروض والكوبونات» (موطنها «التسويق» فقط).
- **عملاء التاجر:** 6 ← 3: جميع العملاء، إضافة عميل، السلات المتروكة. الجدد/النشطون/المحتملون شرائح داخل «جميع العملاء»؛ **المحتملون = سجّلوا بلا طلبات** (التعريف المعتمد).
- **متاجر التاجر:** 7 ← 4: جميع المتاجر (بفلاتر حالة داخلية)، إنشاء متجر، إدارة المتجر، فريق المتجر.
- **الموقع التعريفي للمالك:** 6 قوائم متداخلة ← قائمة واحدة بشارة مرحلة.
- كل قائمة تحمل الآن حقل `status` في مصدر التنقل المركزي: `implemented` أو `{ phase }` تُعرض شارة «قريباً — المرحلة X» صادقة في القائمة الجانبية وصفحة الـplaceholder (بند B-13).

### ما رُبط في Pass A
- **نظرة عامة** (إضافة معتمدة): بطاقات إحصاء حية على رئيسية لوحتي المالك والتاجر، كل بطاقة بتحميلها وخطئها المستقل.
- **دليل التجار** للمالك (بحث، الخطة، الحالة، تفعيل/إيقاف للطلبات المعلقة، رابط إدارة الاشتراك) + **قائمة متاجر المنصة** عبر `GET /platform/stores` الجديدة.
- **صفحات متاجر التاجر**: قائمة بفلاتر + صفحة إنشاء مخصصة + «إدارة المتجر» (إعادة تسمية عبر `PATCH /merchant/stores/:storeSlug`، الرابط العام `/store/{slug}` مع زر نسخ؛ رمز QR مؤجل — يتطلب مكتبة توليد).
- **جميع العملاء** بشرائحها عبر `GET /merchant/stores/:storeSlug/customers` الجديدة (صلاحية `customers.view`) — **وأغلقت معها قائمة العملاء في لوحة الموظف** بنفس المكوّن.
- **«الدفع»** صفحة شفافة: COD مفعّل + البوابات الإلكترونية «قريباً — المرحلة 25أ».
- **«إعدادات المنصة»**: سياسة التسجيل الذاتي حاضرة فيها + أقسام مجدولة بشاراتها.
