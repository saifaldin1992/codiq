# مراجعة الأمان — تشرين الثاني ٢٠٢٦

مرّت هذه المراجعة على ٢٦ بنداً طلبها مالك المنصّة، بنداً بنداً، وعلى الشيفرة الجديدة للسوق (المراحل م٠–م٩).
لكلّ بند: ما وُجد، وما أُصلح، وكيف اختُبر. الإصلاحات كلّها في الكومِت نفسه، والاختبار الجامع
`phase1-backend/tests/security-pass.acceptance.mjs` يشغّل نسخة الإنتاج المبنيّة ويهاجمها من الخارج (يعمل في CI).

## الخلاصة

| | العدد |
|---|---|
| بنود كانت سليمة وتحقّقنا منها بدليل | ١٧ |
| بنود فيها ثغرة أو نقص وأُصلحت | ٨ |
| بنود تحتاج إجراءً منك خارج الشيفرة | ١ (تفعيل دور قاعدة البيانات المقيَّد في الإنتاج) |
| مفاتيح مسرّبة وُجدت في تاريخ git | ٠ — لا شيء يحتاج إلغاءً واستبدالاً |
| ثغرات الاعتماديات (`pnpm audit`) | ٥٩ قبل ← **٠** بعد |

## ما أُصلح

1. **فرض HTTPS** (`http/https-only.ts`، مركَّب في الخادمين). HSTS كان يُرسَل على https فقط، ولا شيء يحوّل زيارة
   `http://` الأولى. الآن في الإنتاج: GET/HEAD على http ← 301 إلى https للمضيف نفسه (نطاقات التجّار الخاصّة تبقى
   تعمل) مع `no-store`، وأيّ كتابة على http ← 426 مرفوضة (لا تُحوَّل كي لا يُعاد إرسال جسمها). فحوص الصحّة مستثناة.
   يعمل فقط حين `CODIQ_PUBLIC_BASE_URL` تبدأ بـ https، فلا تتأثّر البيئة المحلّيّة.
2. **تشفير الاتّصال بقاعدة البيانات**. لا شيء كان يشترط TLS. الآن أيّ عنوان قاعدة بيانات على مضيف غير هذا الجهاز بلا
   `sslmode=require` (أو أشدّ) يُسقط `pnpm env:check`. الشبكة الخاصّة تقول ذلك صراحةً: `CODIQ_DATABASE_PLAINTEXT_OK=true`.
3. **تقييد صلاحيّات قاعدة البيانات** (`deploy/database/least-privilege.sql`). التطبيق يتّصل بصاحب القاعدة، فكلّ استعلام
   يستطيع CREATE/DROP/TRUNCATE ويعدّل سجلّ الهجرات. التطبيق لا ينفّذ أيّ DDL، فالدور الجديد `codiq_app` له قراءة وكتابة
   الصفوف فقط، ودفتر المال وسجلّا التدقيق **إضافةٌ فقط** (لا UPDATE ولا DELETE). جُرّب محلّياً: كلّ عمليّة مدمّرة مرفوضة،
   واختبارات السلّة والدفع والإتمام والكوبونات والعجلة والتذاكر نجحت وهي متّصلة بهذا الدور.
4. **تخمين كوبونات المتاجر**. معاينة الكوبون في واجهة المتجر محدودة بـ ٣٠ محاولة في ١٠ دقائق، لكن ملخّص الطلب في السوق
   كان يصل إلى الدالّة نفسها **بلا حدّ**. صار له الحدّ نفسه لكلّ متسوّق ومتجر، وسقف ١٢٠ لكلّ عنوان IP.
5. **تسجيل النشاط المشبوه**. رموز الدخول الخاطئة ورموز المصادقة الثنائيّة الخاطئة ورموز الاستلام الخاطئة تُرجع 422 فلم تكن
   تُسجَّل حدثاً أمنيّاً؛ وتتابعها هو شكل التخمين. صارت تُسجَّل `security.refused` مع IP (والحارس يتحقّق).
6. **مفاتيح الاختبار في بيئة منشورة**. `CODIQ_OTP_PROVIDER=insecure-log` يكتب رموز دخول المتسوّقين في السجلّ، و
   `CODIQ_ALLOW_OWNER_REGISTRATION=true` يسمح لأيّ أحد بالتسجيل **مالكاً للمنصّة**. تركُ أحدهما مفعّلاً خارج التطوير
   يُسقط الآن `pnpm env:check` ويُذكر باسمه.
7. **مفتاح واجهة في حزمة المتصفّح**. مكوّن خريطة قديم غير مستعمل كان يقرأ `VITE_FRONTEND_FORGE_API_KEY` — وأيّ متغيّر
   `VITE_` يُشحن للمتصفّح. حُذف المكوّن وحزمة أنواعه. فحص الحزمة المبنيّة: لا مفاتيح ولا عناوين قواعد بيانات ولا أسماء أسرار.
8. **الملفّات المخفيّة**. `/.git/config` و`/.env` و`/.DS_Store` كانت تُجاب بصفحة التطبيق (200) — لم يتسرّب شيء، لكنّ كلّ
   ماسح يقرأ 200 «مكشوفاً». أيّ مسار يبدأ بنقطة يُجاب الآن 404 (عدا `/.well-known/`).

وتحديث الاعتماديات: ‎@aws-sdk/client-s3 3.787 ← 3.1175 (لم يعد يعتمد على fast-xml-parser المصاب)، vite 7.3.8،
tailwind 4.3.5، plugin-react 5.2، c8 12، vitest 4، وتجاوزات لـ tar وpostcss وnanoid وpicomatch وrollup وbrowserslist
وglob وminimatch. حزم الإنتاج كان فيها تنبيه منخفض واحد؛ والباقي (٥٨) في أدوات البناء وحدها. الآن صفر في الاثنين.

## ما وُجد سليماً (بالدليل)

| البند | الدليل |
|---|---|
| المصادقة | جلسات موقّعة بنوعها وتُلغى من قاعدة البيانات، مصادقة ثنائيّة للمالك، قفل بعد محاولات خاطئة، رموز السوق ٥ محاولات |
| تشفير كلمات السرّ | bcrypt بكلفة 12 (الاختبار يقرأ التجزئة من القاعدة)، وكلمات أطول من ٧٢ بايت تُجزَّأ أوّلاً |
| التحقّق في الخادم | zod على كلّ مسار كتابة (حارس `validation:guard`) |
| XSS | لا `dangerouslySetInnerHTML` ولا `innerHTML`؛ CSP بلا `unsafe-inline` للسكربت؛ روابط التجّار تُقبل بـ http(s) فقط؛ الاختبار يخزّن `<script>` ويعيده نصّاً في JSON |
| مسارات الإدارة | تدقيق آليّ لـ ٤٦٦ مساراً: كلّ `/platform/*` و`/merchant/*` ومسارات المتسوّق محميّة؛ المتسوّق والتاجر والرمز غير الموقّع يُرفضون |
| الاستعلامات | كلّها مُعامَلة (parameterized)؛ `Prisma.raw` الأربعة على أسماء ثابتة من قوائم مغلقة؛ حقن SQL في البحث يُعامَل بحثاً |
| متغيّرات البيئة | تقرير بيئة يرفض الناقص والضعيف (طول مفتاح الجلسات، مفتاح التشفير، …) |
| حدود المعدّل | الدخول، التسجيل، الاستعادة، رموز السوق (رقم وIP)، التواصل، التذاكر، العجلة، الرفع |
| CORS | لا ترويسة `Access-Control-Allow-Origin` لأيّ أصل غريب؛ كتاباته مرفوضة |
| ترويسات الأمان | CSP، nosniff، frame-ancestors، Referrer-Policy، HSTS، بلا X-Powered-By |
| كعكات الجلسة | HttpOnly، SameSite=Lax، Secure في الإنتاج، `__Host-` حيث تنطبق |
| CSRF | فحص Origin/Sec-Fetch-Site حرفيّاً في كلّ مسار كتابة (حارس `csrf:guard`) |
| انتهاء روابط الاستعادة | ٤٥ دقيقة، استعمال واحد، تُخزَّن مجزّأة |
| الرفع | حجم وعدد محدودان على كلّ رافع، والنوع يُكشف من البايتات لا من الاسم؛ سكربت باسم .png وملفّ ١٢MB مرفوضان |
| الأسعار | السلّة والدفع يسعّران من القاعدة تحت قفل؛ سعر أو مجموع يرسله المتصفّح يُتجاهَل (الاختبار يرسل ١ دينار) |
| وضع التصحيح | أخطاء الإنتاج بلا stack ولا تفاصيل داخليّة؛ لا خرائط مصدر في البناء |
| SSRF والتحويل المفتوح | الخادم لا يجلب إلّا عنوان مزوّد البريد المضبوط؛ كلّ تحويل بعد الدخول مسار يبنيه الخادم |
| تاريخ git | ٣٧ كومِت، كلّ ملفّ أُضيف يوماً: لا مفاتيح AWS/GitHub/Stripe/Google/Slack/npm، ولا مفاتيح خاصّة، ولا كلمات سرّ حقيقيّة — أمثلة واختبارات فقط |
| IDOR في وحدات السوق | كلّ قراءة أو تعديل بمعرّف يأتي بعد قراءة مقيّدة بالمتسوّق أو المتجر |

## ما يحتاجك

- **تفعيل الدور المقيَّد في الإنتاج** (مرّة واحدة): أنشئ `codiq_app` بكلمة سرّ طويلة، شغّل
  `deploy/database/least-privilege.sql` بصاحب القاعدة، واجعل `CODIQ_POSTGRES_URL` يستعمل `codiq_app`
  و`CODIQ_POSTGRES_URL_UNPOOLED` يبقى على صاحب القاعدة (للهجرات). لا أستطيع فعل ذلك من هنا: لا أملك وصولاً لقاعدة الإنتاج.
- **التأكّد من `sslmode=require`** في عناوين Neon/Supabase الحاليّة، ثمّ تشغيل `pnpm env:check` على بيئة الإنتاج.
- اختبارات vitest الخمسة التي تتّصل بـ Neon وS3 الحقيقيّين لا تعمل هنا (تحتاج أسرار الإنتاج) — شغّلها حيث الأسرار.

## إعادة الاختبار

```
pnpm security:pass          # الاختبار الجامع على نسخة الإنتاج
pnpm env:check:test         # قواعد البيئة الجديدة
pnpm logging:guard          # تسجيل الرموز الخاطئة
pnpm audit                  # صفر
```
