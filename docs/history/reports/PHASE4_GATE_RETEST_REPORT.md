# codiq — إعادة بوابة المرحلة الرابعة بعد مواءمة مسار التاجر

**تاريخ الإعادة:** 16 أغسطس 2026.  
**الحالة:** **ناجحة بالكامل.**  
**نطاق الإصلاح السابق:** أضيف فقط دعم الواجهة لمسار الخلفية المقيد بالمتجر `/merchant/stores/{store-slug}/dashboard`، من دون بيانات حقيقية أو منطق أعمال أو تغيير في نموذج العزل.

> أُعيدت بوابة الاختبار كاملة بحسابين وتجربتين جديدتين مستقلتين عن الاختبار الأول. جميع نقاط الفصل الست اجتازت؛ لا يوجد فشل متبقٍ في مسار دخول المالك أو التاجر أو فصل المحتوى أو الأكورديون.

## 1. الحسابات والجلسات الجديدة

| نوع الحساب | البريد التجريبي | ملف الجلسة المستقل | المتجر المقيد |
|---|---|---|---|
| مالك المنصة | `gate4.retest.owner.20260816@codiq.test` | `/tmp/phase4-retest-owner.token` | لا ينطبق |
| تاجر | `gate4.retest.merchant.20260816@codiq.test` | `/tmp/phase4-retest-merchant.token` | `gate4-retest-store-20260816` |

أنشئ الحسابان بحالة `201`، واستخدم لكل منهما Bearer token منفصل تمامًا. أنشئ متجر محلي تجريبي فقط لتوفير سياق `store-slug` الإلزامي لجلسة التاجر.

## 2. دخول المالك وعزله

| التحقق | الدليل | النتيجة |
|---|---|---|
| تسجيل الدخول | `POST /auth/platform/login` | نجح. |
| وجهة التوجيه المعادة | `/platform/dashboard` | مطابقة لمسار لوحة المالك. |
| المسار المحمي | `GET /platform/dashboard` مع Token المالك | `200` و`area="platform_owner"`. |
| عبور إلى مساحة التاجر | Token المالك إلى مسار متجر التاجر | `403` و`IDENTITY_BOUNDARY_DENIED`. |
| الدليل البصري | `/platform/dashboard?open=merchants` و`/platform/dashboard?open=orders` | ظهرت لوحة المالك فقط. |

## 3. دخول التاجر وعزله

| التحقق | الدليل | النتيجة |
|---|---|---|
| تسجيل الدخول | `POST /auth/merchant/stores/gate4-retest-store-20260816/login` | نجح. |
| وجهة التوجيه المعادة | `/merchant/stores/gate4-retest-store-20260816/dashboard` | مطابقة الآن لمسار واجهة مدعوم. |
| المسار المحمي | `GET /merchant/stores/gate4-retest-store-20260816/dashboard` مع Token التاجر | `200` و`area="merchant"`. |
| عبور إلى مساحة المالك | Token التاجر إلى `/platform/dashboard` | `403` و`IDENTITY_BOUNDARY_DENIED`. |
| الدليل البصري للمسار الفعلي | `/merchant/stores/gate4-retest-store-20260816/dashboard?open=stores` | ظهر هيكل لوحة التاجر بدل 404. |

## 4. إصلاح عدم توافق المسار

كان المسار الفعلي لخلفية التاجر صحيحًا من ناحية العزل، لكن الواجهة لم تكن تعرفه. أضيفت مطابقة Wouter للمسار التالي فقط:

```text
/merchant/stores/:storeSlug/dashboard
```

ويحوّل مكوّن لوحة التاجر هذا المسار داخليًا إلى سياق الجذر البصري للوحة، لذلك يظل الشريط الجانبي والصفحة الرئيسية والحالة النشطة متسقة. تأكدت اللقطة الجديدة من أن `/merchant/stores/gate4-retest-store-20260816/dashboard` لا يعرض 404.

## 5. Store Switcher وفصل صفحات المحتوى

ظهر Store Switcher البصري في أعلى شريط لوحة التاجر بعنوان **«متجري الافتراضي»** ووسم **«Store Switcher · تجريبي»**. لم ينفذ أي تبديل أو قراءة بيانات، كما هو مطلوب.

| صفحة المالك | صفحة التاجر | النتيجة |
|---|---|---|
| `/platform/dashboard/site/pages` | `/merchant/dashboard/storefront/pages` | مساران ومكوّنان وسياقان مختلفان تمامًا. |
| `المنصة ← الموقع التعريفي ← الصفحات` | `المتجر والمحتوى ← صفحات المتجر` | لا توجد قائمة مشتركة أو تداخل بصري أو توجيه بديل. |

التقطت لقطات مستقلة للمسارين؛ صفحة التاجر تؤكد نصيًا أنها تخص صفحات المتجر المحدد فقط وليست صفحات الموقع التعريفي للمنصة.

## 6. الأكورديون في اللوحتين

| اللوحة | الحالة الأولى | الحالة الثانية | النتيجة |
|---|---|---|---|
| المالك | `/platform/dashboard?open=merchants` | `/platform/dashboard?open=orders` | فتح «الطلبات» أظهر فروعها وحدها بعد طي «التجار والمتاجر». |
| التاجر على مساره الفعلي | `/merchant/stores/gate4-retest-store-20260816/dashboard?open=stores` | `/merchant/stores/gate4-retest-store-20260816/dashboard?open=orders` | فتح «الطلبات» أظهر فروعها وحدها بعد طي «المتاجر». |

الإعداد `type="single"` ما زال يعمل في اللوحتين، مع انتقال فتح/طي ناعم. كل النقاط الست للبوابة اجتازت.

## قرار البوابة

بوابة المرحلة الرابعة **مجازة تقنيًا**. لم تبدأ المرحلة الخامسة؛ يلزم تصريحك الصريح قبل البدء بها.
