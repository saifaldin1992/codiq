# مطابقة متطلبات ملف CODIQ الأصلي مع المنصة الحالية

**الغرض:** الإجابة الموثقة عن سؤال: هل منصة CODIQ الحالية هي المنصة الموصوفة في ملف المتطلبات المرفق؟  
**تاريخ المراجعة:** 22 أغسطس 2026  
**منهج المراجعة:** مقارنة ملف المتطلبات المرفق مع `CODIQ_SRS_V1.md` وخطة المراحل الرسمية 1–26. لا يُعد هذا التقرير تفويضاً لبدء أي مرحلة أو ميزة.

> **النتيجة المختصرة:** نعم، **CODIQ تسير وفق الرؤية نفسها**: منصة SaaS متعددة المتاجر، تفصل مالك المنصة والتاجر والزبون، وتعتمد عزل المتاجر وقابلية التوسع. لكن **المنصة لم تُنفَّذ كاملة بعد**؛ المنجز هو الأساس التجاري والتقني حتى المرحلة 11A، مع 11B محجوبة بسبب بيئة staging غير مؤكدة. أما كثير من مكونات الرؤية الكاملة، مثل الموظفين بصلاحيات دقيقة، الخطط، النطاقات، الإشعارات، الدفع، الشحن، الـWebsite Builder، واللغات المتعددة، فهي مخططة للمراحل 13–26 وليست موجودة كتطبيق عامل اليوم.

## 1. الحكم العام

| سؤال المطابقة | الحكم | التوضيح |
|---|---|---|
| هل نموذج المنتج نفسه؟ | **نعم** | الملف يطلب SaaS متعدد المتاجر، والخطة وSRS تثبتان نفس النموذج: متاجر مستقلة ضمن منصة مركزية. |
| هل نموذج الأدوار نفسه؟ | **نعم، في الأساس الحالي** | مالك المنصة والتاجر والزبون موجودون بحسابات وجلسات منفصلة؛ موظفو التاجر granular staff مؤجلون للمرحلة 14. |
| هل العزل بين المتاجر موجود؟ | **نعم ومختبر** | `store_id`، علاقات مركبة، Triggers، ورفض IDOR هي أساس التنفيذ الحالي. |
| هل كل ما في الملف عامل اليوم؟ | **لا** | الرؤية أوسع من النسخة الحالية؛ الجزء غير المنفذ موزع عمداً على المراحل 13–26. |
| هل هناك انحراف معماري جوهري؟ | **لا يظهر من الأدلة الحالية** | اعتماد PostgreSQL + Express + Prisma + REST + S3-compatible يحقق المبادئ المطلوبة، مع استبدال بعض التفاصيل العامة بخطة مرحلية أدق. |

## 2. ما يطابق الملف وهو منفذ ومختبر

| متطلب الملف الأصلي | حالة CODIQ الحالية | الدليل الداخلي |
|---|---|---|
| منصة مركزية تنشئ وتدير متاجر مستقلة | **منفذ أساسياً**: متاجر، تجار، منتجات، طلبات وبيانات متجرية معزولة. | SRS §§1، 5، 6؛ الخطة مراحل 1، 5–7. |
| أدوار Platform Owner / Merchant / Customer | **منفذ ومختبر** بحسابات وجلسات منفصلة. | SRS §2 وFR-IDENT-01–05. |
| عزل بيانات التاجر A عن B | **منفذ ومختبر** عبر الخادم والقيود البنيوية واختبارات IDOR. | SRS NFR-01، §5.2، §8.1؛ الخطة مرحلة 5. |
| لوحة مالك المنصة ولوحة التاجر | **موجودتان** بهوية RTL؛ إدارة التاجر/المنتج/الأمر الأساسية تعمل، مع أجزاء Placeholder مقصودة. | SRS §7؛ الخطة مراحل 2، 3، 6–8. |
| منتجات وتصنيفات وصور ومخزون | **منفذ ومختبر**، مع رفع صور S3-compatible وفحص content. | SRS FR-CAT-01–04؛ الخطة مرحلة 7. |
| سلة وCheckout وحساب عميل وطلبات | **منفذ ومختبر** للدفع عند الاستلام COD. | SRS FR-SF-01–12؛ الخطة مرحلة 9 و9B. |
| عناوين ورسوم توصيل حسب المحافظة | **منفذ ومختبر**؛ رسم التوصيل يلتقط داخل معاملة checkout. | SRS FR-SF-09–11. |
| REST API قابلة للتوسع | **منفذ كأساس** تحت `/api` عبر Express؛ التوثيق الآلي والإصدار v1 مؤجلان. | SRS §4.1 و§6.5؛ الخطة مرحلة 20. |
| Database متعددة المستأجرين | **منفذ** بـNeon PostgreSQL وPrisma، مع FKs مركبة وTriggers حيث يلزم. | SRS §§4–5. |
| تخزين قابل للنقل للصور | **منفذ** عبر S3-compatible/Cloudflare R2 بدلاً من تخزين الملفات في القاعدة. | SRS §4.1 وFR-CAT-04. |
| CI وPR وحماية main | **منفذ**؛ CI تكامل حاجب وقاعدة PostgreSQL مؤقتة. | SRS §9 وOPS-01–05؛ الخطة مرحلة 11A. |

## 3. ما يطابق الرؤية لكنه منفذ جزئياً فقط

| نطاق الملف | الجزء المتحقق | الفجوة المتبقية والحالة |
|---|---|---|
| لوحة مالك المنصة | التنقل، إضافة تاجر يدوياً، إشراف قراءة على الطلبات. | إحصاءات مالية وتشغيلية، إدارة متاجر مكتملة، خطط، تقارير وتنبيهات ليست منفذة كتدفقات تشغيلية. جزء من الواجهة Placeholder مقصود. |
| لوحة التاجر | كتالوج، مخزون، طلبات وسياق متجر واحد. | تحليلات، مستودعات، موردون، جرد، تسويق وموظفون بصلاحيات دقيقة غير منفذة. |
| Storefront مستقل | كتالوج ومنتج وسلة وحساب وطلبات وCOD بالعربية. | بحث متقدم، Wishlist، صفحات ثابتة (About/Policies/Contact)، هوية متجر قابلة للتخصيص وSEO شامل مؤجلة. |
| الشحن | رسوم توصيل داخلية حسب المحافظة. | لا يوجد مزود شحن أو إنشاء شحنات أو تتبع أو webhooks. المرحلة 25. |
| النطاقات | تصور معماري وخطة Host-to-store. | لا يوجد default subdomain عامل أو custom domain mapping مثبت بعد. المرحلة 17. |
| الأمان والتشغيل | عزل وجلسات وrate limit وحماية checkout وCI موجودة. | تدقيق OWASP/ASVS شامل، session management المتقدم، monitoring، restore حقيقي وWAF مؤجلة. المراحل 19 و24. |
| النشر المرحلي | Railway جُرِّبت وendpoint الصحة موجود. | staging منفصلة وPublic Domain والنشر التلقائي لم تثبت؛ 11B محجوبة. |

## 5. حدود مقصودة وليست مخالفة للرؤية

> القيود الحالية على الدفع الإلكتروني، OTP/SMS، الكوبونات، تكاملات الشحن، والـWebsite Builder ليست إلغاءً للرؤية الأصلية. إنها **ترتيب تنفيذي آمن**: لا يضاف أي نطاق عالي المخاطر قبل اكتمال العزل، التوثيق، التشغيل، والقرارات المسبقة الخاصة به.

الملف المرفق يصف المنتج النهائي الطموح، بينما خطة CODIQ الرسمية تقسمه إلى مراحل قابلة للاختبار والمراجعة. الترتيب الحالي يحمي الأساس: checkout ومعاملات المخزون وبيانات المتاجر لا يجب أن تتأثر بإضافة UI أو مزود دفع أو ميزات تسويقية قبل الجاهزية.

## 6. نقطة الحالة الحاسمة الآن

لا ينبغي اعتبار CODIQ حالياً منصة عالمية جاهزة بكل خصائص الملف. التوصيف الأدق هو:

> **نواة SaaS تجارة إلكترونية متعددة المستأجرين، مختبرة للمنتجات والطلبات وStorefront وCOD وعزل البيانات، مع خارطة رسمية واضحة لإكمال قدرات التشغيل التجاري والعالمي.**

المعوق الحالي سابق على المرحلة 12: يجب أولاً إغلاق **11B** عبر تأكيد staging منفصلة وPublic Domain وعدم لمس production. بعد ذلك فقط يمكن للمالك أن يقرر، صراحة، بدء المرحلة التالية وفق نطاقها المعتمد.
