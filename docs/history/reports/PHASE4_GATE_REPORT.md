# codiq — المرحلة الرابعة: بوابة اختبار الفصل الكامل

**تاريخ الاختبار:** 16 أغسطس 2026.  
**طبيعة المرحلة:** اختبار وتوثيق فقط؛ لم تُضف أي ميزة أو منطق أعمال أو ربط بيانات جديد.  
**حالة البوابة:** **معلّقة — يوجد عدم توافق مسار يتطلب قرارًا قبل المرحلة الخامسة.**

> نجح عزل الهوية والجلسات، وعرض اللوحتين، وعزل صفحات المحتوى، والأكورديون وStore Switcher البصري. لكن توجيه دخول التاجر الفعلي أعاد مسارًا محددًا بالمتجر لا تدعمه واجهة لوحة التاجر الحالية، لذلك لا يمكن إعلان البوابة ناجحة بالكامل أو بدء المرحلة الخامسة.

## 1. بيانات الاختبار الجديدة

| نوع الحساب | البريد التجريبي الجديد | جلسة الاختبار | سياق المتجر |
|---|---|---|---|
| مالك المنصة | `gate4.owner.20260816@codiq.test` | `/tmp/phase4-owner.token` | لا ينطبق |
| تاجر | `gate4.merchant.20260816@codiq.test` | `/tmp/phase4-merchant.token` | `gate4-store-20260816` |

الحسابان مختلفان عن حسابات المراحل السابقة، وأنشئت لكل منهما جلسة Bearer مستقلة في ملف منفصل. أنشئ المتجر التجريبي محليًا فقط لتوفير السياق الإلزامي لتسجيل دخول التاجر؛ لا توجد بيانات تشغيلية أو عملاء أو طلبات في هذا الاختبار.

## 2. اختبار المالك

| التحقق | الدليل الفعلي | النتيجة |
|---|---|---|
| تسجيل دخول المالك | `POST /auth/platform/login` | نجح بحالة `200`. |
| وجهة التوجيه | `owner_redirect=/platform/dashboard` | **نجح**؛ هذه هي الوجهة الوحيدة المعادة من خدمة المالك. |
| المساحة المحمية | `GET /platform/dashboard` مع Token المالك | أعاد `200` و`area="platform_owner"`. |
| محاولة دخول مساحة التاجر | Token المالك إلى `GET /merchant/stores/gate4-store-20260816/dashboard` | رُفضت بحالة `403` و`IDENTITY_BOUNDARY_DENIED`. |
| الدليل البصري | `/platform/dashboard?open=platform` | ظهرت لوحة المالك وشريطها الجانبي فقط. |

## 3. اختبار التاجر والجلسة المنفصلة

| التحقق | الدليل الفعلي | النتيجة |
|---|---|---|
| تسجيل دخول التاجر | `POST /auth/merchant/stores/gate4-store-20260816/login` | نجح بحالة `200`. |
| مساحة التاجر المحمية | `GET /merchant/stores/gate4-store-20260816/dashboard` مع Token التاجر | أعاد `200` و`area="merchant"`. |
| محاولة دخول مساحة المالك | Token التاجر إلى `GET /platform/dashboard` | رُفضت بحالة `403` و`IDENTITY_BOUNDARY_DENIED`. |
| الدليل البصري للوحة التاجر | `/merchant/dashboard?open=stores` | ظهرت لوحة التاجر وشريطها الخاص وStore Switcher التجريبي. |

### نتيجة مسار التاجر — نقطة حجب

كان التوقع المطلوب في بوابة الاختبار هو الوصول إلى `/merchant/dashboard/`. لكن خدمة المصادقة أعادت فعليًا:

```text
merchant_redirect=/merchant/stores/gate4-store-20260816/dashboard
```

وهذا متسق مع قرار المرحلة الأولى الذي يربط جلسة التاجر بمتجر محدد. ومع ذلك، واجهة المرحلة الثالثة معرفة حاليًا تحت `/merchant/dashboard` فقط. عند فتح مسار التوجيه الفعلي في الواجهة ظهر **404 Page Not Found**، بينما فتح `/merchant/dashboard` يدويًا أظهر الهيكل التجريبي. لذلك:

| نقطة الاختبار | الحالة |
|---|---|
| عزل جلسة التاجر بسياق متجر | ناجح. |
| وصول API لمسار التاجر المحمي | ناجح. |
| تطابق مسار إعادة توجيه API مع مسار الواجهة | **فاشل / غير متوافق حاليًا.** |

لم أصلح هذا التعارض احترامًا لشرط المرحلة الرابعة بعدم كتابة كود أو إضافة وظائف. يلزم قرار لاحق بين جعل الواجهة تدعم مسار المتجر المقيد أو تغيير عقد التوجيه، مع الحفاظ على قيد `store_id` في الجلسة.

## 4. Store Switcher البصري

ظهر عنصر Store Switcher أعلى الشريط الجانبي في لوحة التاجر بالنص **«متجري الافتراضي»** ووسم **«Store Switcher · تجريبي»** في لقطة `/merchant/dashboard?open=stores`. لم يُربط بأي تبديل فعلي، ولم يغيّر متجرًا أو جلسة أو بيانات، التزامًا بنطاق المرحلة.

## 5. الفصل بين صفحات المتجر وصفحات الموقع التعريفي

| لوحة المالك | لوحة التاجر | نتيجة العزل |
|---|---|---|
| `/platform/dashboard/site/pages` | `/merchant/dashboard/storefront/pages` | مساران ومكوّنان وشريطان جانبيان وسياقان مختلفان. |
| سياق: `المنصة ← الموقع التعريفي ← الصفحات` | سياق: `المتجر والمحتوى ← صفحات المتجر` | لا يوجد عنصر تنقل مشترك أو صفحة بديلة أو تداخل بصري. |

التقطت لقطتين مستقلتين للمسارين. تعرض صفحة التاجر نصًا صريحًا يؤكد أنها صفحات المتجر المحدد فقط ومنفصلة بنيويًا عن صفحات الموقع التعريفي في لوحة المالك.

## 6. اختبار الأكورديون بعد التغييرات المتراكمة

| اللوحة | لقطة الحالة الأولى | لقطة الحالة الثانية | النتيجة |
|---|---|---|---|
| المالك | `/platform/dashboard?open=merchants` | `/platform/dashboard?open=orders` | ظهرت فروع «التجار والمتاجر» في الأولى وفروع «الطلبات» وحدها في الثانية. |
| التاجر | `/merchant/dashboard?open=stores` | `/merchant/dashboard?open=orders` | ظهرت فروع «المتاجر» في الأولى وفروع «الطلبات» وحدها في الثانية. |

يتحقق ذلك من استمرار إعداد `type="single"` في كل لوحة: فتح قائمة رئيسية جديدة يطوي السابقة، مع انتقال المكوّن الناعم المعتمد في المرحلتين الثانية والثالثة.

## القرار المطلوب

لا يُنصح بالانتقال إلى المرحلة الخامسة حتى يُحسم عدم توافق مسار التاجر ويوثّق اختبار دخول ناجح ينتهي داخل واجهته المقابلة. عند موافقتك على نطاق الإصلاح، يمكن معالجة المواءمة في مرحلة محددة ثم إعادة تنفيذ بوابة الاختبار نفسها.
