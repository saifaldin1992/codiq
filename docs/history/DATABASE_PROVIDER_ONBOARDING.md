# دليل قاعدة بيانات الإنتاج لـCODIQ

**التوصية الحالية:** ابدأ بـ**Neon PostgreSQL**. إنه يقدم PostgreSQL قياسياً عبر رابط اتصال معتاد، وخطته المجانية دائمة ولا تتطلب بطاقة، مع إمكانية الانتقال إلى خطة مدفوعة بلا حد شهري أدنى عند بدء التشغيل الفعلي. هذه التوصية مناسبة لأن CODIQ يستخدم PostgreSQL وPrisma وExpress بالفعل، ولا تتطلب تغييراً في المعمارية أو في نموذج البيانات. [1] [2]

> **تنبيه تكلفة مختصر:** الأسعار والحدود تتغير من المزود؛ راجع صفحة التسعير قبل ترقية الحساب. القرار النهائي لك. لا أنصح بفتح الموقع التجاري لقبول بيانات عملاء وطلبات حية على الخطة المجانية فقط، لأن حدودها صغيرة ولا تتضمن جدولة نسخ احتياطية. [1]

## 1. لماذا Neon هو الخيار الأبسط الآن؟

| المعيار | Neon | Supabase | Render Postgres |
|---|---|---|---|
| ملاءمة CODIQ الحالية | PostgreSQL قياسي وPrisma وExpress يعملان عبر `DATABASE_URL`. [2] | PostgreSQL قياسي، لكن المنصة تقدم أيضاً خدمات غير مطلوبة الآن. | PostgreSQL قياسي ومُدار بالكامل. [4] |
| البداية السريعة | مشروع جديد ورابط اتصال من شاشة **Connect**. [3] | مشروع جديد ثم رابط اتصال من إعدادات المشروع. | يتطلب إنشاء قاعدة من لوحة Render واختيار instance وتخزين. [4] |
| أقل تكلفة مبدئية معلنة | Free: `$0`، دائم، بلا بطاقة؛ 0.5 GB و100 CU-hours و5 GB نقل شهري. [1] | Free: `$0`، 500 MB، لكنه يوقف المشروع بعد أسبوع من عدم النشاط. [5] | توجد طبقة مجانية بقيود؛ الخيارات المدفوعة مناسبة أكثر للاستمرارية والنسخ. [4] |
| الاتصال المتزامن | Pooled URL افتراضي عبر PgBouncer؛ مفيد للخوادم ذات الطلبات قصيرة العمر. [6] | Pooler متاح وفق الخطة. [5] | عنوان داخلي/خارجي قياسي؛ الأفضل داخلياً عندما تكون الخدمة على Render. [4] |
| الاستعادة والنسخ | Free: سجل استعادة حتى 6 ساعات ولقطة يدوية واحدة؛ Launch: حتى 7 أيام وجدولة لقطات. [1] | Free: لا نسخ تلقائي؛ Pro: نسخ يومي لمدة 7 أيام. [5] | المدفوع يتضمن point-in-time recovery وصادرات منطقية عند الطلب. [4] |

### قرار البدء المقترح

أنشئ مشروع **`codiq-production`** على Neon الآن. يمكن أن يبدأ على Free لتأكيد الربط والهجرات من دون تكلفة، ثم يُرقى إلى **Launch** قبل فتح الموقع للعملاء أو إدخال أي طلبات حقيقية. هذا يحافظ على نفس المزود ورابط الاتصال ومعمارية PostgreSQL، مع تفعيل جدولة النسخ ونافذة استعادة أطول في مرحلة التشغيل الفعلي. [1]

## 2. خطوات التسجيل وإنشاء القاعدة

1. افتح [صفحة تسجيل Neon](https://console.neon.tech/signup) وسجّل بالبريد أو GitHub أو Google. يتيح Neon هذه الخيارات ويأخذك بعد ذلك إلى Console. [3]
2. من Console اختر **New Project**.
3. أدخل الاسم: **`codiq-production`**. الاسم يعرّف مشروع قاعدة البيانات فقط؛ لا يغير اسم مستودع GitHub.
4. اختر إصدار PostgreSQL الافتراضي/الأحدث الذي تعرضه Console، ما لم تكن لديك سياسة توافق محددة لاحقاً. مخطط CODIQ يعتمد PostgreSQL قياسية ولا يستلزم إصداراً خاصاً.
5. اختر المنطقة الأقرب إلى **خادم API النهائي** وليس إلى جهازك. إن لم يكن الاستضافة النهائية محددة، اختر أقرب منطقة متاحة لجمهورك ثم سنضع خادم التطبيق في المنطقة نفسها عند النشر لتقليل زمن الشبكة.
6. اضغط **Create Project**. ينشئ Neon مشروعاً يحتوي فرع إنتاج جذرياً وcompute رئيسياً وقاعدة افتراضية ودوراً افتراضياً. [3]
7. لا تضف جداول تجريبية أو بيانات مثال من SQL Editor. سيطبق CODIQ هجرات Prisma المعتمدة لاحقاً، فتكون القاعدة نظيفة وصحيحة بنيوياً.

## 3. الحصول على رابطَي الاتصال الصحيحين

بعد فتح مشروع `codiq-production`:

1. اضغط **Connect** في Project Dashboard.
2. اختر الفرع الجذري للإنتاج، ثم قاعدة البيانات والدور الافتراضيين.
3. أبقِ **Connection pooling** مفعّلاً وانسخ الرابط الأول. ستجده باسم مضيف يتضمن `-pooler`. هذا هو رابط تشغيل التطبيق:

   ```text
   postgresql://USER:PASSWORD@...-pooler.../DATABASE?sslmode=require
   ```

4. أوقف **Connection pooling** مؤقتاً من النافذة نفسها وانسخ الرابط الثاني. هذا هو الرابط المباشر غير المجمّع للهجرات والنسخ والاستيراد:

   ```text
   postgresql://USER:PASSWORD@.../DATABASE?sslmode=require
   ```

يقدم Neon الرابطين من نافذة Connect؛ الاتصال المجمع مناسب للتطبيقات متعددة الطلبات، أما الهجرات و`pg_dump`/`pg_restore` فتحتاج رابطاً مباشراً. [2] [6]

| المتغير | الاستخدام في CODIQ | نوع رابط Neon |
|---|---|---|
| `DATABASE_URL` | تشغيل Express وPrisma في الموقع | Pooled URL، مع `sslmode=require`. |
| `DATABASE_URL_UNPOOLED` | تشغيل Prisma migrations وأي استيراد أو نسخ إداري | Direct URL، مع `sslmode=require`. |

## 4. كيف ترسل الرابطين بأمان

**لا تلصق الرابطين في GitHub أو ملف `.env` داخل المستودع أو رسالة عامة.** تحتوي هذه الروابط كلمة المرور الخاصة بقاعدة البيانات.

بعد نسخ الرابطين، أرسل رسالة قصيرة فقط: **«أنشأت مشروع Neon وأنا جاهز لإضافة الأسرار»**. عندها أفتح لك حقول إدخال سرية للمشروع باسم:

| الحقل السري | ما تضعه فيه |
|---|---|
| `DATABASE_URL` | رابط Neon المجمّع الذي يحتوي `-pooler`. |
| `DATABASE_URL_UNPOOLED` | رابط Neon المباشر غير المجمّع. |

يُحفظ الرابطان في إعدادات أسرار المشروع، لا في الكود أو سجل Git. بعد استلامهما، سيتم تنفيذ الخطوات الآتية فقط: اختبار اتصال TLS، تطبيق هجرات Prisma على القاعدة الجديدة، فحص الجداول والـTriggers، ثم اختبار كتابة وقراءة بسيط ببيانات تحقق غير حساسة وحذفها بعد التحقق.

## 5. سياسة البيانات والنسخ عند البدء

قاعدة التطوير المحلية تحتوي بيانات اختبار. **لن تُنقل هذه البيانات تلقائياً إلى Neon.** إعداد Neon سيبدأ بقاعدة فارغة ثم هجرات بنيوية فقط، ما لم تطلب لاحقاً استيراداً محدداً ومراجعاً.

عند فتح CODIQ لمستخدمين حقيقيين، يُوصى فوراً بـ:

| الإجراء | السبب |
|---|---|
| الترقية إلى Launch أو خطة تعطي نسخاً مجدولة | Free لا يوفر جدولة snapshots، وتاريخ الاستعادة فيه محدود. [1] |
| إنشاء snapshot قبل كل migration مهمة | نقطة رجوع واضحة قبل تغيير بنية الإنتاج. |
| تقييد صلاحيات الوصول إلى Neon Console | تقليل نطاق الوصول إلى أسرار وبيانات العملاء. |
| اعتماد رابط pooled للتطبيق ورابط direct للهجرات فقط | يحافظ على استقرار الاتصالات ويجنب قيود transaction pooling في أدوات migration. [6] |
| ضبط تنبيه إنفاق عند الترقية | خطط Neon المدفوعة توفر إشعارات إنفاق تنظيمية. [1] |

## 6. البدائل ومتى نختارها

**Supabase** بديل ممتاز عندما تريد لاحقاً استبدال خدمات الهوية أو التخزين أو realtime بخدمات Supabase نفسها. لكنه ليس الخيار الأبسط لـCODIQ الآن: المشروع يملك هوية مستقلة وS3-compatible، وخطته المجانية توقف المشروع بعد أسبوع من عدم النشاط، بينما النسخ اليومية تبدأ في Pro. [5]

**Render Postgres** بديل مناسب إذا قررت لاحقاً استضافة API وPostgreSQL معاً على Render في المنطقة نفسها، لأنه يقدم رابطاً داخلياً ورابطاً خارجياً، وإعدادات تقييد IP، واستعادة زمنية وصادرات في الخطط المدفوعة. لكن Neon أخف وأسرع كبداية منفصلة عن مزود تطبيق محدد. [4]
