# تقرير إعداد قاعدة البيانات الدائمة لـCODIQ

**الحالة:** مكتمل ومتحقق منه.  
**محرك البيانات:** PostgreSQL قياسي على Neon.  
**نطاق التقرير:** ربط بيئة CODIQ بقاعدة PostgreSQL دائمة منفصلة، من دون نقل بيانات اختبار محلية ومن دون إدخال أسرار في الكود أو Git.

## 1. الإعداد المنفذ

تمت تهيئة قاعدة Neon جديدة ثم تطبيق جميع هجرات Prisma المعتمدة عليها. لم تُنقل قاعدة التطوير المحلية أو بيانات الاختبار، لذلك تبدأ قاعدة الإنتاج ببنية نظيفة ومطابقة للمخطط المعتمد. يحتفظ التطبيق بقاعدة PostgreSQL القياسية ومسار Express وPrisma الحاليين؛ لم يُعد إدخال MySQL أو tRPC أو أي خدمة مقفلة إلى البنية.

| بند | النتيجة |
|---|---|
| سر تشغيل التطبيق | `CODIQ_POSTGRES_URL`، رابط Neon المجمّع عبر pooler. |
| سر الهجرات | `CODIQ_POSTGRES_URL_UNPOOLED`، رابط Neon المباشر. |
| متغير النظام `DATABASE_URL` | بقي دون تعديل لأنه محجوز من بيئة المنصة. |
| اختيار الرابط في الخلفية | يفضّل CODIQ السر المخصص على متغير النظام، ويرفض أي رابط غير PostgreSQL. |
| اختيار الرابط في migration | يفضّل الرابط المباشر غير المجمّع للهجرات، ثم يعود إلى رابط التطبيق المخصص عند غيابه. |
| موضع الأسرار | إعدادات أسرار المشروع فقط؛ لا تظهر القيم في الملفات أو Git أو التقرير. |

## 3. إثبات الاتصال والحفظ

أضيف مبدّل اتصال صغير واختبارات Vitest مستقلة للواجهة الخلفية. تم التحقق من الرابطين الفعليين عبر `SELECT 1`، ثم نُفذ اختبار CRUD محدود على الرابط المجمّع: أُنشئ سجل تحقق فريد، قُرئ، ثم حُذف وتأكد غيابه. لا يبقى سجل تحقق في قاعدة الإنتاج بعد انتهاء الاختبار.

| التحقق | النتيجة |
|---|---|
| الرابط المجمّع للتطبيق | نجح اتصال PostgreSQL. |
| الرابط المباشر للهجرات | نجح اتصال PostgreSQL. |
| إنشاء/قراءة/حذف سجل تحقق | نجح عبر رابط التطبيق المجمّع. |
| `pnpm check` | نجح. |
| `pnpm phase1:typecheck` | نجح. |
| اختبارات Vitest لمبدّل الرابط والاتصال والحفظ | 5 اختبارات ناجحة. |

## 4. التشغيل المستقبلي

عند نشر التطبيق، يستخدم Express/Prisma قيمة `CODIQ_POSTGRES_URL` المجمّعة تلقائياً. عند أي هجرة مستقبلية، يستخدم `pnpm phase1:db:migrate` قيمة `CODIQ_POSTGRES_URL_UNPOOLED`. هذا الفصل يمنع مشكلات transaction pooling في أدوات Prisma ويحافظ على الأداء تحت الطلبات المتزامنة.

> **سياسة البيانات:** لم تُنقل بيانات الاختبار المحلية. تبدأ قاعدة Neon بقاعدة بنيوية نظيفة، وتبقى البيانات الجديدة التي يكتبها الموقع في قاعدة PostgreSQL الدائمة. قبل تشغيل موقع حي للمستخدمين، فعّل خطة Neon التي توفر نسخاً مجدولة ونافذة استعادة مناسبة، وأنشئ snapshot قبل كل migration حساسة.

## 6. النتيجة

قاعدة بيانات CODIQ الدائمة مهيأة وتقبل الحفظ، والمخطط والـTriggers والهجرات المعتمدة موجودة عليها. لا يتبقى أي اتصال محلي مطلوب لتخزين بيانات الموقع في بيئة التشغيل التي تتلقى أسرار CODIQ المخصصة.
